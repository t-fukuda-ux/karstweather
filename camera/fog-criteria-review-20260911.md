## 対象と位置づけ

目視はCodexによる画像の見え方の評価で、現地の観測者による正解ではない。旧ラベルや数値を既に見ているため盲検でもない。カメラに写る奥の斜面の見通しだけを扱い、画角外の山並み・谷・雲海や気象学的な視程距離は判定しない。

## 暫定値（上から順に適用）
前提：960×540の同じ画角、mean_all >= 100、近景・中景・遠景の局所コントラストが全て有効。夜間、欠測、画像サイズ変更は判定対象外。

| 条件 | 暫定的な見え方 |
|---|---|
| near_lc < 1.0 かつ far_lc < 0.3 | D：濃霧（手前も霞む） |
| 上記以外で far_lc < 0.3 | B：奥が見えない（手前は見える） |
| 0.3 <= far_lc < 1.5 | H：奥が霞んで見える |
| far_lc >= 1.5 | C：奥まで明瞭 |

「靄＝展望あり」という旧分類は使わない。Cも画角内で明瞭という意味で、気象学的な「霧なし」の保証ではない。near_lcの2.2/3.7だけでH/Cを決める方法は今回の目的には合わなかった。

mid_lcは分類の主条件にせず、Cなのにmid_lc < 3.5なら不整合として要確認。手前の道路を通る車、人、濡れた路面、照明によって近景の数値が変わるため、近景の数値だけで奥の見通しを決めない。

0.3は「奥消失」と「霞んで見える」の暫定境界。9/8 09:50（far=0.28）は斜面の輪郭がごく薄く、どちらに分類するか迷うためU（不確か）とした。確定的な境界の根拠にはしない。霞んで見える例の最小値は0.40。9/9 05:50は濃霧だがfar=0.24あり、朝のノイズにも注意する。

1.5は霞む群の最大0.89と、明瞭群の最小1.72の間に仮置きした値。この空白に今後の画像が入ると境界を修正する可能性がある。9/8 14:50（1.72）は軽い霞みが残るため、明瞭群の端の例として継続確認する。

近景1.0は旧基準を保留採用。手前まで霞む画像は0.12〜0.81だが、9/9 17:50（1.05）は建物がかなり霞み、濃霧/薄霧の境界は曖昧なのでUとした。

## 明日以降の検証方法
1. 初回の基準は fog-criteria-v1.json に固定する。変更時はv2等の別版を作り、旧版の値と成績を残す。
2. まず画像だけでD/B/H/C/Uを付け、その後に数値と候補判定を比較する。現地の人が確認できる場合は別の評価者として保存する。
3. 境界付近（near=0.8〜1.2、far=0.2〜0.4または1.2〜1.8）、近景/遠景の不整合、Cなのにmid<3.5を重点確認。幅は運用上の仮の余裕で、統計的な信頼区間ではない。
4. 要確認以外からも、各区分・朝昼夕を抜き取り確認する。境界例だけでは自信を持って間違える例を見落とす。
5. 画像更新時刻・ハッシュ重複を確認し、同一画像の再取得を成績の母数に重複計上しない。レンズの水滴、画角変更、強い影や車もメモする。
6. 日ごと・区分ごとの一致/不一致とUの件数を残す。特にB（奥消失）をC（明瞭）にする誤りを重視する。修正した日までを再び開発データとし、次の日以降で新基準を検証する。

開発画像の曖昧な2枚・重複1枚を除く34枚では候補分類と今回の目視区分が一致。9/11の参照12枚でも一致した。ただし画像を見てから区分・閾値を整理した結果であり、「精度100%」や将来性能を意味しない。
